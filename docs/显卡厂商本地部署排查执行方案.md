# dengta 显卡厂商本地部署排查执行方案

编制日期：2026-11-13。状态：基于当前源码与本地 TwinSDK 0.5.4 核对的执行方案；尚未制作交付包、验证离线适配或在厂商机器验收。

## 1. 交付目标和边界

厂商仅部署、访问 dengta 交付页面，复现及排查 WebGL2 / Three.js 初始化、真实工厂场景加载和交互问题。默认以完全不访问我方内网、不需要 npm 下载依赖的本地运行作为交付目标。

- 不要求厂商安装平台、编辑器、数据库、案例管理系统或 AI 服务。
- 不要求厂商从 npm 公共源或我方私有源安装 TwinSDK。
- 我方完成生产构建；TwinSDK 和 Three.js 通过构建进入前端 JavaScript。厂商不需要 node_modules，也不需要现场重新构建。
- 厂商无需部署“案例管理系统”，但必须拿到当前已发布案例对应的场景文档、模型、材质纹理、元数据和案例专属功能包。这些是页面渲染输入，不能因为 SDK 已打包而省略。
- 本次验收范围是三维渲染及现有本地演示交互。AI、真实业务中台、视频服务及其他外部系统不作为成功条件，交付版应明确标记不可用或按需关闭入口。

## 2. 已核实的项目事实

1. package.json 依赖 @twin/web-sdk ^0.5.4；本地已安装版本为 0.5.4，内含 Three.js r180。打包时应记录实际依赖版本和摘要，不以范围声明代替实际版本。
2. src/layout/scene.vue 调用 createTwinApp，传入 serverUrl、deliveryCode、autoUpdate、pixelRatio。
3. public/config.json 当前 serverUrl 指向我方私网 10.67.8.183:5184/api；直接复制 dist 不能让厂商离线加载三维场景。
4. SDK 的 DeliveryClient 通过 POST /delivery/token 获取 token，再访问 /delivery/release、/delivery/custom-apis 和 /objects/{hash}。自动更新还访问 /delivery/status。对象下载后会进行内容哈希校验。
5. 工厂交付端 lighthouse/twin.js 依赖 app.customApi 获取案例能力；只带模型文件不足以保证业务交互运行。
6. SDK 当前通过 new WebGLRenderer({ antialias: true, alpha: false, powerPreference: 'high-performance' }) 初始化。WebGL2 初始化失败是本次必须保留、复现的行为。
7. src/utils/statusEnum.js 将 E_CAPABILITY_UNAVAILABLE 泛化为 WebGL2 提示。交付排查版应保留 code、message、details 和堆栈，避免遮盖真实错误。
8. 入口为 /#/page_2/2。public/vtk 下有本地仿真资源；sourceUrl 及若干环境变量仍含外部或内网地址，交付前需按实际路由请求检查并处理。
9. vue.config.js 配置 productionSourceMap: false、publicPath: './'；当前 npm 构建脚本使用 Windows set 语法。构建在我方完成，避免把这类差异带到国产 Linux 现场。

## 3. 推荐方案：前端生产包 + 固定场景快照 + 本地交付读取服务

访问链路：厂商浏览器 → 本机静态 HTTP 服务 → dengta 生产页面；页面通过同一本机服务提供的交付接口读取固定场景快照及对象。

本地服务只读取本次交付目录里的静态快照，不包含平台的账号系统、案例编辑发布、数据库或管理页面。它是交付包的启动与资源读取组件，不是让厂商重新部署平台。

优先采用保持 createTwinApp 调用链不变的交付接口适配方式，减少针对厂商环境另写加载链导致的复现偏差。此适配器尚未实现，必须经过后续验证。

### 3.1 快照内容

- 当前 /delivery/release 响应：sceneId、name、revision、document。
- 当前 /delivery/custom-apis 响应，以及 definitions 引用的实际功能包对象。
- 场景实际引用的全部内容哈希对象，包括模型、元数据、纹理和其他资源；不能只收集第一层 contentHash。
- 元数据、材质、自定义功能包继续引用的资源，及模型内嵌/外置资源、动态加载文件、解码器、worker 等需要逐项确认闭包完整。
- 当前页面使用的本地 VTK 资源、图片、字体及其他静态资源。
- 任何必须保留的外部 URL 资源应本地化并校验引用；修改哈希校验对象时必须重算摘要及所有上游引用，不能简单替换文件内容。
- 清单记录场景 revision、SDK 版本、资源数量、总大小和 SHA-256。发布包排除平台密钥、生产 token、私有源认证和无关项目配置。

导出可由我方在现有已授权环境完成，无需给厂商平台管理权限。导出工具应在无法确认资源完整时失败并指出缺项，而不是生成看似可运行的缺件包。

### 3.2 本地接口适配范围

- POST /api/delivery/token：按照 SDK 所需响应结构返回仅用于本机测试快照的会话数据；有效期、刷新和错误响应都要能通过 SDK 校验。不是复制生产 token，也不代表生产授权。
- GET /api/delivery/release：返回冻结的发布响应。
- GET /api/delivery/custom-apis：返回冻结的案例能力定义。
- GET /api/objects/{hash}：原样返回快照对象字节，确保 SDK 哈希校验通过；仅允许清单内合法哈希。
- GET /api/delivery/status：返回同一冻结版本，防止意外触发更新。
- AI 等未纳入验收的接口应显式提示未启用，不能伪造成功响应。

接口路径源于当前 SDK，具体请求方法、字段、会话校验、内容类型及动态导入行为需在实现时以 SDK 实际运行结果复核。服务默认绑定 127.0.0.1，只暴露本次快照；需要跨机器访问时另行调整绑定与访问控制。

### 3.3 交付配置

- 页面默认通过 http://localhost:3666/#/page_2/2 访问，不双击 index.html。
- config.json 的 serverUrl 指向本机启动服务的绝对地址，例如 http://localhost:3666/api；当前 SDK 要求 URL 格式，不直接写相对 /api。
- autoUpdate 设为 false，pixelRatio 保持 1，冻结版本并减少不必要变量。
- 模型、材质、默认渲染参数与当前问题现场保持一致；不得为了使页面显示而悄悄关闭抗锯齿、改用软件渲染或换成简单测试模型。
- 若厂商从其他机器访问服务，应显式配置可达地址，避免 localhost 指向错误机器。离线校验优先以本机浏览器访问 localhost 完成。
- 启动脚本检查端口、静态入口、快照清单、对象缺失与摘要；失败时输出具体缺项并停止。

### 3.4 启动环境

厂商浏览器承载 WebGL2 渲染；本地服务仅承担 HTTP 和文件读取。必须先确认厂商系统、CPU 架构、浏览器完整版本和驱动版本，再选择启动服务的运行时。

优先复用厂商已有且可用的运行时，或随包提供与操作系统及 CPU 架构匹配的经验证运行时。不能承诺一个 Windows x64 可执行文件覆盖国产 Linux、ARM64、LoongArch 等环境。启动组件不能以厂商联网 npm install 为前提。Docker 仅在厂商已有且可用时作为可选方式，不设为默认前置条件。

## 4. 更轻量的联网方案及适用条件

若厂商能够访问我方现有交付服务，可只交付 dist、启动说明和配置，继续使用远端授权及案例资源。无需本地读取服务和场景快照。

但必须先验证厂商实际网络可达、交付码有效、页面 Origin 获授权、浏览器跨域访问成功、全部对象可下载；仅“能 ping”或“接口在我方可用”不算验证。当前私网地址不能假定在厂商网络可达。

因此此模式只适合网络条件已确认的现场，不应作为默认的独立本地交付承诺。

## 5. 分阶段执行

### 阶段 A：冻结复现基线

记录当前源码/文件摘要、SDK 和 Three.js 实际版本、依赖锁文件、场景 revision、页面配置、浏览器/系统/GPU/驱动信息。保留已有截图和原始失败日志。冻结后续对比使用的场景和渲染参数。

### 阶段 B：制作本地交付包

在我方环境构建 production dist；导出已发布场景快照和完整对象；实现并校验最小交付接口适配器；生成配置、平台对应的启动脚本、版本资源清单与故障采集说明。SDK 无需发布到公共源。

建议目录：

```text
dengta-gpu-repro/
  web/                  # production dist；TwinSDK 已打入 JS
  snapshot/             # release、custom-apis、objects，冻结版本
  launcher/             # 本地服务和目标系统启动脚本
  diagnostics/          # WebGL2 探测页及采集说明
  manifest.json         # 文件、版本、摘要和构建环境
  README-厂商运行说明.md
```

### 阶段 C：交付前验证

1. 在干净目录解压，不借用原项目 node_modules、工作目录、浏览器缓存或我方私网服务。
2. 使用 localhost 访问；禁用外网/内网依赖，在冷缓存下观察全部请求，记录任何非预期外部访问；本地服务未漏文件。
3. 在一台已知可正常运行当前 WebGL2 场景的参考机器上完成真实场景首帧及交互。
4. 验证相机旋转缩放、设备选择聚焦、至少一个依赖 customApi 的设备状态/仿真交互，以及本地 VTK 加载。
5. 重新启动和重复加载，核对版本、资源清单与日志，确认可复现。
6. 在厂商同类操作系统/CPU 架构环境验证启动组件；无法取得对应环境时明确记录“该运行时未验证”，不能填通过。

### 阶段 D：厂商现场排查

先运行与业务无关的 WebGL2 探测页，再运行同一包的 dengta 完整场景。探测页分别测试默认上下文参数与项目参数，并记录 context creation error、上下文丢失、渲染器信息及实际上下文属性。探测成功不能替代真实场景验收。

先记录本机物理桌面结果，再记录远程桌面结果；两者作为对照，不预设远程软件是根因。采集 GPU 状态页、系统/GPU/驱动/浏览器版本、控制台和网络日志、包版本摘要、首帧耗时及复现步骤。GPU 状态页导出前注意检查可能包含的机器标识。

抗锯齿、GPU 后端或驱动调整只作为有记录的对照实验，每次仅改变一个变量；不得覆盖原始默认配置或将软件回退成功记为目标显卡硬件渲染通过。

## 6. 验收口径：把保证落实为实际通过记录

| 层次 | 通过标准 | 未通过时结论 |
| --- | --- | --- |
| 包完整性 | 解压校验通过，运行时/端口/资源齐全，页面与本地接口启动成功 | 交付或启动环境问题，先修包 |
| 自包含 | 冷缓存且我方网络不可达时仍能读取完整固定场景和功能包 | 存在遗漏外部依赖，不得交付为离线包 |
| 参考机器 | 原参数下真实场景和约定交互通过 | 包或适配实现尚未验证完成 |
| 厂商基础图形 | 原参数 WebGL2 上下文与基础绘制通过 | 浏览器/驱动/图形栈排查入口 |
| 厂商完整场景 | 同一版本首帧、相机、点选和约定交互通过，未使用未声明的软件回退 | 继续定位完整场景特有能力或稳定性问题 |

交付包可以通过上述流程保证依赖齐全、部署可复现；当前已出现 WebGL2 创建失败的硬件环境能否完成渲染，必须由厂商环境实测确认，不能通过打包提前保证。包部署成功、错误成功复现和问题修复后场景运行成功是三个独立记录。

## 7. 执行前必须收敛的信息

- 厂商操作系统与版本、CPU 架构、浏览器完整版本。
- 完全离线还是允许连接我方交付服务；未确认时按离线目标制作。
- 当前已发布工厂案例的快照导出来源、资源授权范围及冻结版本。
- 厂商已有可运行的本地 HTTP 服务/运行时；没有则提供相应架构版本。

本方案不要求开放 TwinSDK 公共源，也不要求厂商部署平台或案例管理系统。需要随包携带的是本次页面真正使用的固定案例资源及本地读取能力。
