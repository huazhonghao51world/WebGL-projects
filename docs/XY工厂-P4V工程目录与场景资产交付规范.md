## 2. 后续文件放哪里

下表路径均相对于 `assets/xy-factory/`。当前只有 `models/` 已建立，其余目录首次有实际交付物时再建。

| 目录 | 放什么 | 随包说明 |
| --- | --- | --- |
| `models/` | 园区、建筑、楼层、设备的交付模型；含内嵌动画的 GLB 也放这里 | 明确新增还是替换，注明保留了哪些楼层或设备节点 |
| `textures/` | 模型或场景实际外链的贴图及材质资源 | 保持导出时的相对引用。若是整包内部依赖，保留其原目录结构，无需另外复制一份 |
| `points/` | 点位原件和结构化点表（JSON 或 CSV） | 每点提供稳定 ID、名称、类型和 XYZ；有楼栋、楼层、模型节点或监控通道 ID 的一并提供，缺失项标未提供 |
| `animations/` | 独立的运动资产、片段清单、运动接口说明 | 记录作用模型及节点、片段名、时长、初始状态、循环、触发、暂停、停止和复位方式。能提供一段验证视频或复现步骤更好 |
| `scene-packages/` | 场景配置包 `xy-scene-profile/dist/`（材质、补光与性能代码的构建产物），以及可独立导入的场景整包 | 保留入口、版本、清单、锁文件与全部依赖；写清适用平台版本、导入步骤和已知限制 |
| `references/` | 俯视图、关键视角、配准数据、楼层或节点映射表 | 标注对应模型或变更单。引用新图时不要覆盖 `docs/xy-first-delivery/` 的首批快照 |
| `README.md` | 当前这批资产如何配套、从哪个入口开始、还有哪些未交付 | 文件名、相对路径、依赖或使用方式变了，同步更新说明 |

整包若采用场景组自有格式，请照原结构交付，并写明格式版本、入口、引用规则及所需解码器或扩展。采用 Twin DSL 时，提供目标平台实际接受的版本、`scene.json`、匹配的资产锁、资产清单及文件；若不兼容，先给最小可导入样例，由平台与接入方确认适配方式。首批建筑模型曾需要兼容转换，后续导出配置变更时请附可导入小样和验证结果。

## 3. 更新时必须保住的约定

1. **同一资产沿用同一相对路径。** 更新 `L_Building2.glb` 就签出并替换原文件，用 P4V 记录历史；不要堆 `_final`、`_v2` 等平行副本。必须改名、拆包或合包时，附旧路径 → 新路径及受影响的引用；新增文件建议用稳定的英文名、数字和短横线，扩展名小写。
2. **场景、建筑和点位用同一坐标基准。** 不要单独居中、缩放或旋转一栋楼再交。首次交付或基准变更时，提供坐标单位、轴向、原点、导出变换、至少三个不共线的共用基准点，以及一段已知长度；参考图标出校核位置。现有 GLB 按本地米制、Y 向上、右手系接入，现场实尺有待用已知尺寸核对。
3. **交互用稳定 ID，不能只靠显示名或导出索引。** 有点选、显隐、定位或运动需求的楼层、设备保留可识别的独立节点，并提供 `对象 ID → 模型相对路径 → 节点稳定 ID / 路径`。节点改名、拆分、删除时附新旧映射。监控点提供位置不等于已接视频；若要支持朝向或视角，另给朝向或 `position + target`。
4. **一项可验收变更放在同一单。** 资产与同步变化的贴图、点位、节点映射和说明一起提交；未修改的模型不重复提交。模型、动画和场景包须能从约定目录解析所有依赖，不引用个人电脑绝对路径。保留源交付原件；接入时临时生成的兼容 GLB 由导入流程管理。

二开应用仍在独立工作区。此 P4V 项目不提交前端源码、应用配置、工作台整套工程、构建目录、依赖缓存、临时导出和账号密钥。场景团队交付的可导入场景包或 XY 专属场景编排属于场景资产；应用里用于调用它们的 UI 和接口代码属于二开。

## 4. P4V 提交方法

1. 在 **Depot** 中确认项目路径，切换到能映射该目录的 Workspace，对 `assets/xy-factory/` 执行 **Get Latest Revision**。如果有人已签出同一个二进制资产，先确认谁交哪一版；GLB 无法像文本一样合并。
2. 新建独立的 Pending Changelist。更新已有文件：**Check Out** 到该单，再替换。新增：把文件放进对应目录后 **Mark for Add**；GLB、贴图和压缩包应识别为 `binary`。改名或删除时用 P4V 的 **Move/Rename** 或 **Mark for Delete**。批量导出如需 **Reconcile Offline Work**，只在 `assets/xy-factory/` 下预览并勾选本次文件。
3. 提交前核对 Pending 列表：预期修改都已打开，外部依赖齐全，没有多带源码、构建文件或无关资产。至少本地打开一次场景，按参考图查位置、材质和涉及的楼层、点位或动画；尚未在目标平台验证的，注明“待平台验证”。
4. 写清变更单描述后 **Submit**。交接时给接入方变更单号、改动范围、验证方法以及需联动的点位或节点映射；需要回查时，以该单的文件版本为准。

变更单描述示例：

```text
[XY工厂][场景资产] 更新生产楼二层布局

文件：models/L_Building2.glb、references/production-2f-node-map.csv
坐标：原点、单位、轴向不变；楼栋标签与监控点位置不变。
节点：二层两处节点改名，旧节点 → 新节点见映射表。
依赖：材质与贴图内嵌，无新增外链；动画无变更。
自测：本地打开确认二层显隐和已知尺寸；目标平台待验证。
```
